面向视觉质检 / 看图识别业务：为什么模型会「瞎猜」，以及如何用「主张 → 举证 → 再验」的有限循环压住幻觉。

## 一、问题从哪来

业务里让 VLM「看图说话」时，常见两类错误：

1. **看花了**：某块区域模糊、遮挡、光照差，模型硬认成某个物体。
2. **先验带偏了**：图里证据不足，模型靠常识补全——厨房里「应该有碗」，沙滩上「应该有遮阳伞」。

后者尤其危险：话通顺、置信度还不低，但图上未必有。一次调用、一句结论，很难区分这两种失败。

要把幻觉从「偶发体验问题」变成「可诊断、可拦截的系统问题」，需要两块认知底座，再落到一条可实现的验证闭环。

## 二、两个关键概念

### 高注意力区域

AI 看图时，并不是平均看整张图。它会对某些区域更关注。

例如让模型描述：「一只狗在草地上奔跑。」模型可能主要关注狗的身体、狗的头、草地。这些被重点关注的地方，就叫 **高注意力区域**——可以粗略理解成：模型眼睛盯得最用力的地方。

补充两点，避免误解：

- **高注意力 ≠ 一定看得清**：它表示「对生成答案更重要」，不等于分辨率够、细节真在。
- **注意力随任务变**：问「什么品种」可能盯脸和毛色；问「在哪儿」可能盯背景。同一张图，不同问题，高注意力区域可以完全不同。

### 语言先验，以及「压住语言先验」

**语言先验**就是模型的文本经验：厨房里常有微波炉、餐桌上常有碗、沙滩上常有遮阳伞、马路上常有汽车。这些经验有时有用，也会导致瞎猜。

**压住语言先验**的意思是：当图片证据不足时，不让模型只靠常识乱补。

例如：模型想说「有碗」，但视觉证据显示它看的地方更像盘子，不像碗——系统就应降低「碗」的概率，提高「盘子」或其他更贴合视觉的类别。

一句话：有图靠图；证据不足时宁可说不清，也不用常识脑补。

## 三、用「遮挡」诊断幻觉从哪来

一个很实用的排查手法：

1. 模型说「碗」。
2. 你怀疑它盯着某块模糊区域在猜 → 把那块 **遮住 / 抹掉**。
3. **遮住后改口了** → 幻觉很可能挂在那块视觉证据上（看不清就硬认）。
4. **遮住后仍说「碗」** → 更像已被场景常识 / 语言先验定调：它先入为主认为「该有碗」，于是会换个地方继续找理由。

所以遮挡实验测的不是「会不会幻觉」，而是 **幻觉从哪来**：局部看花了，还是先验先行、事后找补。

注意：遮挡会改变整图布局和注意力，单次结果不要定死；宜多试几处、多张图。

## 四、业务里的「反幻觉识别流程」

可以把质检识别设计成多级闸门，而不是一次 VLM 调用定生死：

| 步骤 | 做什么 | 目的 |
|------|--------|------|
| 1. 初始识别 | 让 VLM 列出图中物体 | 产出主张 |
| 2. 证据提取 | 对每个物体追问位置（坐标）与视觉证据 | 绑定「看见了什么」 |
| 3. 低置信过滤 | 低置信不当事实验收 | 先降风险 |
| 4. 关键物体复核 | 业务关键类做第二轮追问 | 成本聚焦 |
| 5. 局部裁剪验证 | 可疑区域裁剪后独立再认 | 打断全景先验 |
| 6. 交叉模型验证 | 检测模型（如 YOLO）或另一 VLM | 换一套归纳偏置 |
| 7. 最终输出 | 四态结论 | 可运营、可人工接管 |

**四态输出（建议固定）：** 确认存在 · 疑似存在 · 不存在 · 无法判断。

「无法判断」必须挂动作（重拍、人工、默认不通过），否则流程漂亮，业务上仍会被迫乱猜。

### 这套思路强在哪

- **可解释**：主张带位置与证据，便于抽检和追责。
- **分层成本**：不是每张图打满全流程，关键物体才深检。
- **机制对症**：裁剪 + 遮挡 + 检测器，能区分「局部看花」与「先验带偏」。
- **结论可运营**：疑似 / 无法判断可进人工或降级策略。

### 落地时要注意的坑

1. **同模型连环问会传递误差**：第 1 步列错，后面都在错假设上打转。关键项尽量 **盲测**（局部识别不要问「这里有没有碗？」）。
2. **口头置信度常校准很差**：高置信幻觉很常见。更可信的是：证据是否具体、裁剪是否一致、跨模型是否一致。
3. **坐标也会幻觉**：能编「碗」，也能编框。要校验框是否在图内、面积是否合理，并与裁剪 / 检测对齐。
4. **裁剪会丢上下文**：关系类判断（「桌上的盘子」）裁太死会失真；可用「紧裁剪 + 带少量上下文的次局部」对照。
5. **调用次数会乘起来**：全链路可能是多次 VLM + 检测；必须做漏斗，否则延迟和费用按倍数涨。

## 五、核心闭环：主张 → 举证 → 再验

把上面流程收成一条可实现的主链路：

```text
主张 → 举证 → 不一致？→ 裁剪 / 遮挡 / 换模型再认 → 仍不一致？→ 继续或标「无法判断」
```

这就是视觉质检场景里的 **验证 Loop**：不是无限生成，而是 **有限轮次的对抗式核实**。

它和 Loop Engineering（循环工程）的对应关系是：

| Loop 要素 | 在反幻觉里的落点 |
|-----------|------------------|
| 触发 | 一张待检图 / 一条初始识别主张 |
| 感知 | 全图、裁剪图、遮挡图、检测结果 |
| 推理 / 计划 | 是否一致、下一刀用裁剪还是换模型 |
| 执行 | 再问 VLM、跑 YOLO、写回状态 |
| 可验证目标 | 四态之一 + 证据链完整；或达到 max_rounds |
| 停止条件 | 确认 / 不存在 / 无法判断；禁止死循环烧 token |

## 六、如何实现（工程骨架）

### 数据结构

每条物体主张是一个可流转状态的对象：`label`、`bbox`、`evidence`、`confidence`（仅作参考）、`status`（确认存在 / 疑似存在 / 不存在 / 无法判断 / 待验证）、`history`（每轮仲裁记录，审计用）。

### 主循环逻辑（伪代码）

```text
claims = VLM全图列物体()          # 主张：只做一次

for claim in claims:
    claim = VLM追问证据与坐标(claim)  # 举证

    for round in 1..max_rounds:      # 建议 2～3
        if 一致性通过 and 非关键类:
            status = 确认存在; break

        # 不一致或关键类 → 再验
        crop_result  = 裁剪后盲测识别()
        mask_result  = 遮挡后是否仍坚称原label()
        det_result   = 检测模型交叉(可选)

        status = 仲裁(claim, crop, mask, det)
        写入 history

        if status in {确认存在, 不存在, 无法判断}:
            break

    if 仍待验证:
        status = 无法判断
```

### 「不一致」怎么判（规则层）

不要只信模型自评。至少检查：bbox 是否在图内、面积是否合理；evidence 是否空泛（「看起来像」而不描述形状 / 开口 / 材质）；证据词与 label 是否冲突；置信是否过低。

### 仲裁表（裁剪 / 遮挡 / 检测）

| 现象 | 倾向结论 |
|------|----------|
| 裁剪结果 = 原 label，遮挡后改口，检测也命中 | **确认存在**（靠该区域视觉） |
| 裁剪改成别的类（盘），遮挡后仍说碗 | **疑似先验幻觉** → 疑似或不存在 |
| 裁剪说有、检测没有 | **疑似** 或再一轮 |
| 多轮仍打架 | **无法判断** |

**盲测要点：** 局部识别只问「图中主要物体是什么？」，不要问「这里有没有碗？」——否则语言先验又被你喂回去了。

### Prompt 约束示例

全图列举时：

```text
只输出 JSON：
{"objects":[{"label":"...","bbox":[x1,y1,x2,y2],"evidence":"...","confidence":0-1}]}
禁止补充场景常识里「应该有」但图中看不见的物体。
```

举证时：

```text
针对 label 与 bbox：
1) 支持该判断的视觉特征（形状/开口/材质）
2) 若证据不足请把 confidence 降到 0.4 以下
不要用「厨房常有碗」这类理由。
```

### 生产漏斗（控成本）

```text
L0 全量：一次轻量识别（可用更便宜模型 / low effort）
  ├─ 非关键 & 一致性通过 → 确认存在
  └─ 关键 / 低置信 / 冲突 → L1 裁剪 + 遮挡
           └─ 仍疑 → L2 检测器 / 第二模型
                    └─ 仍疑 → 无法判断 → 人工 / 重拍
```

日调用量大时（例如数十万张图），**绝不能七步全开**；用关键类白名单决定谁进深检。

## 七、和 Cursor `/loop` 的边界

- **业务线上的验证 Loop**：跑在你的服务里，按张 / 按主张闭环，有硬停轮次。这是本文要落地的东西。
- **Cursor `/loop`**：适合研发侧定时抽检、回归样例、对比「遮挡后是否还说碗」。它是质检助手，不是高 QPS 推理引擎。

两者可以配合：线上跑验证闭环；线下用 loop / eval 集盯住先验幻觉是否回潮。

## 八、最小落地顺序

1. 单模型跑通：`list → evidence → crop/mask → 规则仲裁 → 四态输出`
2. 加上检测器交叉与关键类白名单漏斗
3. 建一小撮「先验幻觉」回归样例（遮挡后仍坚称某物）
4. 改 Prompt / 阈值后必须重跑这批样例，防止效果回退
5. 再考虑与巡检 Prompt 评测平台、自我学习循环打通

## 九、一句话收束

VLM 反幻觉的本质，不是让模型「更会说」，而是：

> **逼每一条主张交出视觉证据，并用裁剪、遮挡、跨模型在有限轮次内互相拆台；拆不倒才确认，拆到打平就承认无法判断。**

高注意力告诉你「它盯哪」；压语言先验告诉你「别靠常识补」；验证闭环则把这两件事工程化，变成质检系统可执行的 Loop。
